# 複数写真の登録・移行

通常雑学、地図雑学、承認待ち候補は、それぞれ最大10枚の写真を登録できます。保存順がアプリの横スワイプ表示順になり、先頭が表紙です。アプリは写真の下に現在位置を示す丸と枚数を表示します。1枚だけの場合は丸を省略します。

## 管理画面

- 「管理・編集 → 写真の確認」の「選択した写真を採用して本番へ反映」は、承認記録に続けて本番DBへ全写真と出典を保存します。失敗時は採用を保持し、「採用済みの写真を本番へ反映」で再試行できます。
- 「写真の確認」の「写真の管理対象」で通常雑学と雑学MAPを切り替えます。Mapも候補の複数枚承認から本番DBへの自動反映まで対応します。Mapの収集回は別管理で、未収集なら空になります。
- Mapの手動登録・編集は「本文・写真の編集 → 管理対象：雑学MAP」です。R2候補・複数ファイル・写真別出典・並べ替えに対応し、「写真なし／写真あり」で絞り込めます。
- 開発用・内部配布・TestFlightも本番API経由で同じ本番DBを参照します。旧版は `image_url` の先頭1枚、新版は `image_urls` の全写真を表示します。

- R2の画像一覧では複数の写真にチェックを付け、「選択した写真をまとめて追加」で一覧の末尾に追加できます。ページを移動してもチェックした写真は保持します。同じ写真は重複しません。
- ファイル選択では複数枚をまとめて選べます。1枚あたり12MB以下です。既存の写真の後ろに追加されます。
- URL / R2キーは1行に1枚ずつ入力してまとめて追加できます。
- 矢印で順序を変え、「外す」で一覧から除きます。登録・更新を押すまでDBには保存されません。
- 登録済み写真のトリミングでは、変更する写真を選べます。他の写真は保持されます。
- 写真を外してもR2のオブジェクトは削除しません。他の雑学で共有している写真を引き続き使えます。
- 各写真の「写真の出典」に出典URL、撮影者、提供元を入力できます。アプリでは表示中の写真の下に作者名・ライセンス・加工ありを小さく表示し、タップすると作品名・指定クレジット・加工内容などの全文と元画像・ライセンスのリンクを開けます。原文はDBに保持します。未登録の場合は表示しません。雑学本文の `source` は写真の出典として使用しません。
- 署名付きスマホ編集画面も複数選択・並べ替え・削除に対応します。アップロードやDB保存に失敗した後も、成功済み写真を再利用して再試行できます。

## データ移行と反映

`trivia`、`map_trivia`、`trivia_candidates` に `image_urls` と `image_sources` のJSON列を追加します。従来の `image_url` は削除せず、既存の写真を1枚目として移行します。移行は繰り返しても登録済みの順序・出典を変更しません。既存写真の出典は自動補完しないため、管理画面で登録してください。

通常雑学とMapには写真公開ツール用の `image_credit` と `image_credit_metadata` も追加します。写真確認ツールは通常雑学を `trivia`、Mapを `map_trivia` に保存し、Mapの確認画像・承認履歴・公開画像にはR2の `map/` を含む別プレフィックスを使います。同じ数値IDでも通常雑学を上書きしません。

Mapの詳細は地図・収集済み一覧の両方から表示できます。詳細を開く際にAPIの最新写真・出典を取得し、端末の解放日時・解放状態を保持します。現地条件を満たさない未解放スポットでは写真も表示しません。

API・管理画面の起動時に移行処理が実行されます。個別に実行する場合は、対象環境の設定を確認し、`apps/api` から次を実行します。

```powershell
python -m scripts.migrations.migrate_trivia_images
```

通常のRender起動コマンドで呼ぶ `migrate_trivia_candidates` にも組み込まれています。API・管理画面を更新してから新しいアプリを反映してください。旧アプリには従来の `image_url` で表紙1枚を返します。新しいアプリは旧APIからの写真1枚の応答にも対応します。

## 保存API・外部ツール

新しい管理クライアントは、写真全体を順序付き配列 `image_urls` で送ります。空配列 `[]` は全写真を解除する指定です。配列の省略または `null` は旧クライアントとの互換用で、`image_url` から補完します。

既存項目への更新では、両方の写真項目を省略すると写真を保持します。従来の `image_url` だけで表紙を変更した場合は2枚目以降を保持し、空文字で全写真を解除します。

写真の出典は `image_sources: {"trivia/first.webp": "https://example.com/original-photo"}` のように写真URL / R2キーと対応付けて保存します。出典の省略は既存値を保持し、`{}` で全出典を解除します。並べ替えても出典は同じ写真に紐付き、写真の削除時にはその出典も解除します。公開APIでは出典のキーにも写真と同じ公開URLを返します。

外部ツールがAPIを経由せずDBへ直接書く場合も、必ず同一トランザクション内で両方の列を更新してください。`image_url` だけの直接SQL更新では、登録済みギャラリーに反映されません。別リポジトリの写真公開ツールも対象です。

```python
item.image_urls = ["trivia/first.webp", "trivia/second.webp"]
item.image_url = item.image_urls[0]  # 全解除の場合は None
db.commit()
```

同じ画像は重複を除いて保存します。公開APIではR2キーを公開ベースURLで補完し、壊れた過去の画像参照は読み飛ばすため、1枚の不正なURLで雑学全体の読み込みが失敗することを防ぎます。
