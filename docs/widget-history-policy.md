# 雑学の閲覧履歴を登録する条件

## 登録ルール

- 毎日雑学のウィジェットが1つ以上設置されている場合、その日の配信分（最大3件）を履歴に登録する。ホーム画面とロック画面の両方を対象とする。
- アプリでは、現在のカードを左右にスワイプした時点で、その雑学を履歴に登録する。
- カードの取得・先読み・詳細を開くだけでは登録しない。ウィジェットのプレビューでも登録しない。
- 同じ雑学は、ウィジェット・スワイプ・再送のどの経路で登録しても1件として扱う。
- ウィジェットを削除しても過去の履歴は保持する。取得できなかった日数分の自動補完は行わない。

日付は端末の現地時刻の午前2時で切り替える。ウィジェットの更新はiOSと通信状態に依存するため、設置しているだけで毎日の取得が保証されるわけではない。

## 実装

`WidgetCenter.shared.getCurrentConfigurations` の結果に `kind == "TriviaWidget"` が含まれるかを確認する。設置状態を固定のフラグとして保存せず、アプリへの復帰・バックグラウンド更新・ウィジェットの更新時に確認する。確認失敗や旧ネイティブモジュールでは未確認として自動登録を行わない。設置状態の反映タイミングはWidgetKitに依存する。

`GET /trivia/today` は当日の配信候補を固定する `DailyAssignment` を作るが、閲覧履歴は作らない。`GET /trivia/widget` は `widget_installed=true` のときだけ、返却する当日分の最大3件を履歴に追加する。今日の割り当てが既に存在する場合も履歴登録を行うため、アプリ起動後にウィジェットを追加したケースに対応する。

`widget_installed` の省略時は既存ウィジェットとの互換性のため `true` とする。新版クライアントは判定結果を明示する。通常のスワイプは既存の認証付き `POST /history` を使用する。履歴登録は共通処理を通し、PostgreSQLではユーザー単位のトランザクションロックで同時登録による重複を防ぐ。

過去の日次割り当てに選ばれただけの未読雑学は、後日の配信候補に戻る。履歴の保存済みデータは削除しない。

## 反映と確認

APIを先に更新し、その後にiOSアプリとウィジェット拡張を再ビルドする。Swiftとネイティブモジュールを変更しているため、JavaScriptのOTA更新だけでは全変更を反映できない。

自動テストは履歴API・設置判定のブリッジ・アプリへの復帰・スワイプ・バックグラウンド更新を確認する。iOSビルド後には次を実機で確認する。

1. ウィジェット未設置でアプリを開き、詳細だけを開いても履歴が増えない。
2. カードをスワイプするとその1件が追加され、戻して同じカードを再度スワイプしても重複しない。
3. アプリで当日のカードを取得した後にウィジェットを追加すると、その日の最大3件が履歴に入る。
4. アプリを開かず翌日のウィジェット更新を成功させると、その日分が追加される。
5. ウィジェットを削除して設置状態が更新された後は、自動登録が止まる。
6. プレビュー表示だけでは登録されない。通信失敗時はキャッシュを維持し、再取得時に登録を再試行する。
7. 午前2時の日付変更と、ホーム画面・ロック画面での設置判定を確認する。
