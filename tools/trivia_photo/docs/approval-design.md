# 既存管理画面で写真を確認する

実装済み。毎日雑学のStreamlit管理画面 →「管理・編集」→「写真の確認」で使う。
本文の編集へ戻るには「本文・写真の編集」を選ぶ。新しい管理サイトは起動しない。

## 操作

- 収集回、状態、ID・タイトルで絞り込み、5件ずつ表示する。
- おすすめと最大2枚の別候補を16:9で比較する。作者・ライセンスを表示し、詳細から出典・条件・全体版を開ける。
- 各候補の「この写真を採用する」にチェックを付け、「選択した写真を採用して本番へ反映」を押す。複数枚を採用でき、先頭を表紙として全写真の作者・出典・権利確認とともにR2へ記録する。承認後に利用条件を再確認し、公開用R2へコピーして本番Neonへ反映する。
- 別候補は写っている対象の利用条件を人が確認してから採用する。対象との関係は参考画像として記録する。
- 「理由を付けて選び直し」は、対象画像・理由・補足をR2へ記録する。却下した画像は同じ雑学で再提案しない。
- 「保留」は写真と履歴を保持し、未承認として残す。
- 「最新の状態を読み直す」で別の画面やCodexの更新を取り込む。読み直すまでは表示していた写真の版で操作し、更新後の古い画面からの承認は拒否する。

管理画面では採用とDB反映を一続きで行う。反映に失敗した場合は採用済みの写真を保持し、画面の「採用済みの写真を本番へ反映」で再試行できる。保留・選び直しはDBを更新しない。
複数枚の場合は `approved_photos` に採用した全写真を保存し、再読み込み後もチェック状態を保持する。反映時は全写真の条件を検証してから公開用コピーを行い、`image_url`（表紙）・`image_urls`（全写真）・`image_sources`（写真ごとの出典）を同じDBトランザクションで更新する。既存の単一写真の記録も扱える。
クレジット必須の写真は、アプリの表示対応完了まで反映しない。毎日雑学側は写真別の出典表示に対応済み。

## 選び直しをCodexへ渡す

「管理画面で選び直し待ちにした写真を集め直して」と依頼する。
Codexは次を読み、収集手順の検索要件へ理由を反映し、元のバッチの該当IDを`search --refresh`する。

```powershell
.\.venv\Scripts\python.exe -m trivia_photo review-queue
# 特定の収集回だけ読む場合
.\.venv\Scripts\python.exe -m trivia_photo review-queue --batch <batch>
```

検索時・選定時・採用時に却下履歴を照合する。CommonsのページID、出典URL、表示版・全体版のハッシュを比較する。
別バッチでも同じ雑学IDの履歴を参照する。別の雑学に同じ写真を使うことは一律に禁止しない。
履歴はR2のバッチJSONに保存し、選び直しの際に旧記録も保持する。PCの作業フォルダを削除しても消えない。
現状は収集・選定時に過去バッチを読み取る方式であり、収集回が大量になったら雑学IDごとの索引を追加する余地がある。

## 接続・運用

既存アプリの変更は`apps/api/admin_dashboard.py`の切り替え7行と、`apps/api/services/photo_review.py`の接続に限定した。
共有の実装は`trivia_photo/admin_ui.py`と`approval.py`。管理画面の認証は既存のものを使う。
同じPCでは同階層の`trivia_photo`を読む。現在の管理画面のPython環境で必要なライブラリの読み込みを確認済み。
管理画面を起動済みなら再読み込みする。コードの再読み込みが無効なら同じ管理画面を再起動する。

別環境で運用する場合は、管理画面のPython環境へ本パッケージをインストールする。
`pip install "<trivia_photoのパス>[admin]"`、または同階層配置と`requirements.txt`のインストールを使う。
別の場所のチェックアウトは`TRIVIA_PHOTO_ROOT`で指定できる。
R2接続設定は共有し、`R2_REVIEW_BUCKET_NAME`・`R2_REVIEW_PREFIX`を収集環境と一致させる。
環境変数を優先するため、ハーネス固有の設定を使う場合は管理画面の環境にも同じ値を設定する。
公開バケットの確認用プレフィックスは非公開領域ではない。

画像の加工・表示はメモリのみ。R2が画像・判断履歴の正本。追加のAI API、定期実行は使わない。


## 通常雑学と雑学MAPの切り替え

2026-10-16の指示により、Mapも候補確認・複数枚承認・本番DBへの自動反映に対応する。
既存管理画面の「管理・編集 → 写真の確認 → 写真の管理対象」で「通常の雑学」または「雑学MAP」を選ぶ。
採用ボタンで、選択中の対象へ全写真と写真別出典を同時に反映する。先頭1枚は旧版用のimage_urlにも残す。
通常雑学はpublic.trivia、Mapはpublic.map_triviaへ保存する。管理画面と同じ本番DBを使う。
Mapの確認画像と履歴はR2_REVIEW_PREFIX/map、公開写真はR2_TRIVIA_IMAGE_PREFIX/auto/mapへ分ける。
同じ数値IDでも対象をまたいだ承認・上書きはしない。通常雑学の既存バッチと公開URLは維持する。

CLIは全コマンド共通で、コマンド名より前に --target map を付ける。省略時は従来どおり通常雑学。
例: .\.venv\Scripts\python.exe -m trivia_photo --target map collect --limit 5
例: .\.venv\Scripts\python.exe -m trivia_photo --target map list --batch latest
例: .\.venv\Scripts\python.exe -m trivia_photo --target map review-queue
収集は引き続き手動で、collectだけでは候補を検索しない。collect.mdに従ってsearch・目視・select・verifyまで進める。
Mapの候補が未収集なら確認画面は空になる。対象を指定して写真収集を依頼する。
Mapのimage_credit/image_credit_metadata列を含む毎日雑学側のmigrate_trivia_images移行を先に適用する。
旧ローカル画像のmigrate-localは通常雑学専用。Mapに流用しない。
